# Deploy the original DataPulse repository on Vercel

Repository: https://github.com/HardikMalik14/datapulse-engine

## Apply this update in PowerShell

Download `DataPulse_Original_Repo_Vercel_Update.zip` into Downloads. Run these one at a time, continuing only when the previous command succeeds:

```powershell
cd "$HOME\Downloads"
git clone https://github.com/HardikMalik14/datapulse-engine.git DataPulse-original-deploy
cd .\DataPulse-original-deploy
Expand-Archive -LiteralPath "$HOME\Downloads\DataPulse_Original_Repo_Vercel_Update.zip" -DestinationPath . -Force
git add .
git commit -m "Add interactive DataPulse lab and Vercel deployment"
git push origin main
```

This is a local clone of your existing GitHub repository, not a new GitHub repository. If that local directory already exists, use the existing checkout and pull `main` before extracting. Do not run `git init` or force-push.

## Deploy

1. Open https://vercel.com/new and import **HardikMalik14/datapulse-engine**.
2. Framework Preset: **FastAPI**. Root Directory: `./` (repository root, not `datapulse`).
3. Leave Build, Install and Output Directory overrides disabled. No environment variables are needed.
4. Click Deploy. After it is Ready, click Visit.
5. The synthetic sample runs automatically once. Check the before/after matrix, Pipeline audit and Drift & features tabs.
6. Change seed from 42 to 17, then click Run pipeline. The data and diagnostics are recalculated.
7. Click Download messy sample CSV, select Upload your CSV, upload that file, choose `churned` as target and Classification, then run.
8. Click Export data + pipeline to download the ZIP generated by that run.
9. Add the production `.vercel.app` URL to your portfolio and repository About → Website field.

Official framework reference: https://vercel.com/docs/frameworks/backend/fastapi

## Runtime and repository changes

- Adds `index.py` (FastAPI), `public/index.html` (browser UI), `.python-version` (3.12), `vercel.json` (60-second function maximum) and an explicit `index:app` Vercel entrypoint in the existing `pyproject.toml`.
- Pins the runtime dependency set tested with this deployment, and retains pytest/httpx in `requirements.txt` so the original CI install step runs both engine and web tests.
- Makes one small pandas compatibility fix in `datapulse/core/encoding.py`: categorical blocks replace missing entries with `where(...).infer_objects(copy=False)` rather than relying on deprecated implicit `fillna` downcasting. The original repository treats these FutureWarnings as test failures. The full original engine test suite passes after the fix.
- The original CLI, reporting library, data generator, pipeline ordering, and inference/resampling separation remain available.
- No external database, API key, account or live-data feed is used.

## What actually runs

The service uses the existing DataPulse engine. It calls `fit_transform` only on training rows and transforms the holdout with the fitted chain. It audits drift in the engineered feature space by applying the same inference mapping to the raw train/reference and holdout frames. Resampled synthetic training rows are not used as the drift reference.

The browser displays returned schema, missingness, stage reports, scaling decisions, feature-selection scores and drift data. Result cards are calculated from the actual request. Changing settings requires another run; a failed request leaves the previous successful results visible with an error message.

The synthetic generator provides a classification target, mixed dtypes, identifiers/constants, missing cells, formatted currency, collinearity, high-cardinality categories and optional planted holdout drift. Its Base missingness setting is not the final whole-table missingness rate: some missingness is deliberately structured or planted separately.

Uploaded CSVs are split randomly using the selected seed, stratified for classification. They do not represent a temporal production-monitoring exercise. Regression skips resampling. This website does not train a downstream classifier/regressor, calculate predictive accuracy, or claim that preprocessing necessarily improves a model.

## Limits and uploads

- CSV only, UTF-8 encoding, up to 1 MB.
- Uploads: 100–1,200 rows and 3–35 total columns, including target. Unique, nonempty headers, names under 120 characters, text cells under 300 characters. Infinite numeric feature values are rejected; missing feature cells are allowed.
- Classification: 2–5 target classes, at least eight rows per class. No missing target labels.
- Regression: finite numeric target values, no missing targets.
- Synthetic demonstration: 200–1,200 rows.
- Holdout fraction: 20–40%.
- Downloads: compressed export limited to 2 MB to keep the web response bounded. A larger export returns a message asking for fewer rows/features.
- One CPU-heavy run at a time per service process; concurrent requests receive a retry message.

Data is sent to the deployment for processing. The app creates request-scoped temporary files for serialization and removes them after packaging. It does not create an upload database or persist a fitted user pipeline between requests. The browser holds the current export until refresh.

## Export contents

- `train_processed.csv`: processed training matrix plus target; includes synthetic rows if resampling ran.
- `holdout_processed.csv`: transformed holdout plus target, preserving holdout row count.
- `datapulse_pipeline.joblib`: fitted inference transformer chain, excluding resampler.
- `datapulse_pipeline.meta.json`: version/config/schema metadata generated by the engine.
- `pipeline_config.json` and `run_report.json`.
- `README.txt` with usage notes.

Use the original source package with compatible library versions to load the exported artifact with `DataPulseEngine.load(...)`. The site never accepts or deserializes an uploaded joblib/pickle. Its artifact comes only from the pipeline it just fitted.

For training, use `train_processed.csv`. Running the fitted artifact on the raw training rows would apply full-data target-encoding mappings, which are different from the out-of-fold encodings emitted by `fit_transform`. This is intentional and follows the existing engine contract.


## If something fails

- **404:** choose repository root `./` and FastAPI, not the inner `datapulse` package.
- **Missing module:** confirm all package files remain in the repository and the update's `index.py`, `public`, dependencies and config were committed.
- **Timeout:** reduce row count, choose median imputation and IQR-only outlier detection.
- **Export too large:** reduce rows/features.
- **CSV error:** inspect target/task selection and the limits above.
- **Vercel build failure:** expand Build Logs and share the first error and nearby lines.
